## Architecture recorded before implementation

- Shared version-1 flat topic graph (`root_id`, `topics` with ID, nullable parent ID, plain text and collapsed flag). Validate exactly one matching root, unique IDs, connected acyclic ancestry, maximum depth 64, valid UTF-8/plain strings up to 500 characters and a 64 KiB serialized graph budget. There is no fixed per-parent subtopic cap. Bound layout work by this byte budget; collapsed descendants remain saved.
- Share deterministic two-sided tree layout and an accessible React topic editor/static preview between native Board objects, Markdown widgets and legacy Document atoms. Use theme colors, no external assets/services or new dependencies. Only an active Board map exposes editing controls. Keep changes in existing undo/autosave/revision systems and prevent pending topic text/composition from being lost on blur, navigation or conflicts.
- Native Board kind `mindmap`, content format 1 and `data.mindmap`; additive migration upgrades spatial envelope/default to 7 without rewriting saved object data. Explicitly adapt older supported Board snapshots/drafts; reject maps in pre-7 envelopes and unknown map versions. Full/PATCH validation share the graph validator. Downgrade refuses while saved maps remain, including Trash.
- Canonical Markdown retains format 2 and adds the versioned atomic directive `:::orbium {"kind":"mindmap","mindmap":{...}}` with no body. Existing reserved-directive validation rejects unsupported kinds/versions in older servers. Legacy Documents use a `mindmap` atom containing the same graph. Normal source, rich widget lifecycle, autosave/conflict guards, copy/reorder and formatting-preserving exports remain the ownership boundaries.
- Topic text is plain text, never HTML, page mentions, attachment IDs or Node hierarchy. Search/plain text/statistics include labels. Formatting-preserving Document export keeps the directive; plain Markdown export degrades explicitly to a fenced text topic outline instead of silently dropping data. No Board import/export or whole-account portability changes.
- Stop after formatting, lint, types, PHP syntax, build, migration inspection/application where available and a report with exact manual checks/expected results, limitations and commit suggestions. No later phase is authorized.
