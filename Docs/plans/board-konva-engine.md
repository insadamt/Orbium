# Konva hybrid engine — implementation contract

Authorized 2026-11-01 by the supplied migration task and “go ahead”. Milestones A–G are internal steps of this one engine migration, not approval for other product phases. Browser acceptance and production performance measurements remain the user's manual work.

## Audit and composition decision

`BoardWorkspace` owns tools, selection, autosave and the camera. `BoardRecordStore` owns immutable content, grouped history and revisioned persistence. `BoardObjectCard` owns native editing, rectangular hit targets, borders and resize handles. Original and Instant Scene modes currently share SVG drawing/shape presentation. Instant Scene additionally prepares HTML/Mermaid/PDF content. Its default and URL-over-session override precedence must stay unchanged.

Freehand currently runs `prepareBoardDrawingPoints` over every accumulated sample and rebuilds its SVG path each frame. Erasing reconstructs fragments for every drawing before its bounds check, for every sweep. Pointer events already coalesce and gesture previews already stay outside React; retain those mechanisms. Camera painting uses refs and CSS layout zoom. Existing finite WAAPI/CSS effects, not a perpetual graphics loop, own decorative motion. No production trace establishes the thermal cause.

Use direct Konva operations in a focused adapter. React and React DOM are actually **19.3.0** in the lockfile. A React-Konva reconciler is unnecessary for imperative pointer painting; install only official MIT Konva, leaving React unchanged.

Reviewed primary guidance: [Konva performance tips](https://konvajs.org/docs/performance/All_Performance_Tips.html) and [automatic redraws](https://konvajs.org/docs/performance/Batch_Draw.html). The implementation additionally checks the installed 10.9.1 Layer/Shape/Canvas source and pins that version because its custom Path2D drawing accesses the typed native context.

Canvas cannot interleave its internal nodes with arbitrary external HTML. Compile the presented layer order into contiguous graphics bands separated by native visual barriers. HTML blocks, shape labels and selected/hovered drawing shells are barriers. Each band owns one surface cropped to its graphics bounds intersected with the viewport; the active ink preview has a separate viewport surface so input does not redraw completed graphics. Native cards keep their ordering, editors, focus, hit targets, menus and handles. CSS z-index is integral: multiply all Board object stacking positions by two in Konva mode and use odd graphics/even native slots. Retain outgoing outline barriers for 160ms while their existing CSS fade finishes.

**Bound the number and total pixel allocation of surfaces.** Limit to six presented graphics bands, including existing retained/offscreen shells, plus one input plane; cap pixel ratio at two and total scene pixels at 24 million, reserving input capacity. If composition exceeds either budget, use original SVG graphics for the entire presented scene and expose the effective renderer/fallback reason in canvas data attributes and diagnostics. Never merge bands across an HTML barrier, flatten an editor, allocate a viewport canvas per object, or silently reorder content. This is an explicit architectural limitation of bounded HTML/canvas composition: arbitrary alternating overlaps cannot have both an unlimited canvas-only migration and a fixed number of canvas planes. The original path is a compatibility fallback, not evidence that those scenes were accelerated. No duplicate graphics presentation runs for an object. Pixel ratio above two needs explicit visual review; native content keeps its original density.

The focused visual stage is implemented with standalone passive Konva Layers, Groups and Shapes. A Konva Stage would allocate additional viewport buffers and input listeners for each HTML-separated band. Installed Konva source inspection confirms these custom scene functions can draw through a Layer directly. Resize only scene canvases; leave unused hit canvases zero-sized. Override automatic batch scheduling for these owned layers only, without changing global Konva settings. Explicit Board paint boundaries own redraws. No React-Konva dependency, rasterized block screenshot, serialized Konva node or second pointer owner is added.

Use the existing authoritative camera for all projection. Publish imperative camera/geometry notifications at existing paint boundaries, without a second camera state or mutation observer scanning card styles. Keep original 10–400% navigation for Konva, with a separate browser-local view key. Use passive Konva graphics, because changing from existing rectangular DOM selection to stroke-only hit selection would change behavior. Canvas stages do not take pointer ownership from native content.

## Drawing and erasing

Buffer coalesced input in refs. For opt-in drawing, prepare consecutive 64-sample chunks with the existing Off/Light/Strong profiles, cache completed geometry, and recompute only the unfinished tail. Each chunk/tail has up to 65 prepared vertices (or its unsimplified controls when required); remaining global allowance constrains the final tail, preserving the 6,000-point saved bound. Preview and saved numeric points must use the same prepared geometry; there is no release-time whole-stroke replacement. Chunk boundaries retain their shared endpoint. This changes smoothing scope and curve-sampling allocation on newly drawn strokes and requires manual visual acceptance, especially sparse fast curves, handwriting and zigzags. Existing saved ink is never re-smoothed. Preserve span, coordinate and byte limits.

Keep highlighter alpha applied once to the preview surface to avoid darker chunk joins. Cache native Path2D geometry for completed drawing fragments and use the existing shape path functions, including all seven validated kinds. Keep rich shape labels in their existing DOM editor. Path Pen keeps its anchor controls and draft commands; cache placed segments while updating only the hover tail.

Build a drawing-only spatial candidate index once per eraser gesture, cache original fragments, and preserve the existing swept-capsule clipping and fragment reconstruction. Only dirty drawings receive preview changes; completion remains one ordinary Board commit. Cancel restores canonical graphics without touching history.

## Lifecycle, motion and review

Draw on invalidation only. Suppress hit graph drawing for passive surfaces; use a deliberate pixel ratio and total allocation budget. Dispose canvases, listeners, cached paths and queued frames on unmount. Hidden tabs stop pending graphics work; returning invalidates once. Existing CSS/WAAPI effects must continue to include graphics through explicit bounded motion integration, with reduced-motion behavior retained. Keep SVG construction for deletion previews independent of inactive rendering. Reuse Instant Scene's HTML/PDF preparation in Konva mode so reader state, rich previews and pinning survive the graphics migration.

Panning/zooming redraws cropped graphics bands and reuses their cached paths, rather than relying solely on DOM translation. Canvas rendering can still be expensive for dense views. The 24-million-pixel limit bounds roughly 96MB of scene RGBA storage, not total browser/GPU/driver/PDF/editor memory. There is no measured claim that these trade-offs beat original rendering on all hardware.

Keep `?boardRenderer=konva` opt-in, alongside original/instant URL and session overrides. No toolbar, CSS visual identity, server API, history boundary, database migration, archive or Board format change. No automated tests or browser automation are authorized. Run formatting, lint, TypeScript, production build and whitespace checks, then report exact manual acceptance and missing production CPU/GPU/frame/memory/thermal evidence. Do not make Konva the default without later explicit approval.
