# M3 — Live Preview, slash commands and Markdown shortcuts

Date: 2026-10-07. Branch: `editor/codemirror-markdown`. Status: implemented for manual review; browser correctness and matched performance evidence are pending. The user explicitly approved proceeding with M3 and requested `/` and Markdown shortcuts in this phase. This brings the slash-command slice forward from M5; it does not authorize all remaining M4/M5 features. M2 source-mode baseline measurements were not supplied before this work; no performance GO or tuning result is claimed.

## Implemented

- Markdown documents open in Live Preview, with a button to switch to Markdown source. Both presentations keep the same EditorView, text, selection and undo history. Source mode retains line numbers; Live Preview uses the existing document column and a reading font. The initial M3 implementation retained M2's bounded internal scroll area; the 2026-10-08 review correction below switches Live Preview to page scrolling.
- Lezer syntax ranges drive H1–H6 heading styles, bold, italic, strike, inline code, bullet/number markers, quotes, interactive task checkboxes and dividers. Ordinary safe inline links show their labels and open with Ctrl/Cmd+click; native keyboard/screen-reader activation is also handled. Plain clicks retain editing behavior. Internal links use stable canonical IDs and current authorized application routes, never rewriting source to installation URLs.
- Formatting syntax is hidden away from the caret. Entering an inline expression or selecting it reveals its Markdown; entering a block marker reveals that marker. Selection/find jumps therefore address the actual source. Syntax replacements are supplied as atomic ranges for cursor navigation. Selecting all / copying uses CodeMirror's canonical Markdown selection, not a separate HTML serialization.
- Live Preview builds decorations from `visibleRanges` and the incremental syntax tree, rebuilding on relevant content/selection/viewport/focus/parser/editing-permission changes. It does not traverse the whole body to generate a separate rendered document. It uses line decorations and inline widgets/replacements only: no block widgets or replacements crossing line breaks are supplied from the view plugin. Vertical rich-widget layout remains an M4 design gate. New profiling samples use `codemirror.preview.decorations`.
- Task clicks change one checked-marker character through an editor transaction, so autosave and undo/redo handle them. Checkboxes have native keyboard controls and accessible labels, check current editing permission, and update DOM in place when their source position/state changes. Inactive retained editors cannot modify tasks or run the slash picker.
- `/` opens the installed CodeMirror completion UI at a block start or after whitespace in ordinary prose. It supports filtering by labels/aliases, Up/Down, Enter, Tab, Escape and pointer selection. Ctrl+Space remains Search Master. Code, links, raw HTML, table source, dollar-math lines and reserved metadata source do not open slash completion. Picking a block changes a bounded source range as one undo group; commands insert a block rather than implement the entire later turn-into UI.
- The menu supplies Text, Heading 1/2/3, Bullet list, Numbered list, Checklist, Quote, Callout, Code, Image, File, Table, Mermaid, Math block, Inline math and Divider. Rich commands insert their valid canonical source. Table/callout/code/math/Mermaid source is editable now; full rich widgets remain M4.
- Image/File commands open the existing file upload flow and insert owner-scoped `orbium:attachment/<id>` references after success. Image choice checks supported MIME types both before and after upload. The slash insertion range maps through concurrent edits; if its source text changed, completion preserves those edits and displays the exact reference for manual placement. Cancel/failure leaves the slash text. Pending uploads guard navigation/tab removal/unload, and only one upload runs at a time per editor.
- Typing `# ` / `## ` / `### `, list/task markers, `> `, `---`, and complete inline Markdown formats Live Preview without discarding the source. Existing CodeMirror Enter/Backspace continue/exit lists and quotes. Enter on an unclosed top-level backtick/tilde fence inserts its closing fence and puts the caret inside. It does not duplicate an already parsed closing fence. Tab/Shift+Tab indent/outdent list context; otherwise ordinary Tab focus behavior remains. CodeMirror's Ctrl+M tab-focus escape (Shift+Alt+M on macOS) remains available.
- Ctrl/Cmd+B, Ctrl/Cmd+I and Ctrl/Cmd+Shift+X wrap/unwrap selected text with Markdown delimiters. They avoid applying formatting in literal/source-only contexts. Slash/fence/format actions use explicit history boundaries.
- M2 autosave/revisions/retry/guards/byte limits remain the persistence path. Changing presentation never queues a save. Search retains its explicit M2 **Markdown-source** policy and exact source positions; selected hidden syntax is revealed. The UI explains this policy rather than claiming logical-text search across markers.

## Library decision and limits

The recommended approach reuses the already selected CodeMirror/Lezer engine. An optional choice was presented; no separate wrapper, renderer or menu framework was installed. Orbium owns the decorations, bounded command transactions, upload bookkeeping and link policy.

| Library | Version | Role / limitation |
| --- | --- | --- |
| `@codemirror/autocomplete` | Existing 6.20.3 | Picker placement, filtering integration, keyboard handling, focus and accessible menu behavior. It does not define Orbium block commands or upload semantics. Its Ctrl+Space binding is deliberately excluded. |
| `@codemirror/lang-markdown` / Lezer Markdown | Existing 6.5.2 / transitive 1.8.0 | Incremental standard-Markdown/GFM syntax ranges and native continuation behavior. These are not a complete Orbium dialect validator or CommonMark semantic-reference resolver. |
| `@codemirror/view` | Existing 6.43.13 | Decorations, inline widgets and atomic ranges. Its installed API explicitly prohibits block widgets and newline-covering replacements from viewport/function-provided decorations. It does not provide Notion interaction parity by itself. |
| `@lezer/common` | Existing 1.5.3, now direct `^1.5.3` | Direct ownership of imported syntax-node types. No installed/locked package version changes in M3. |

Primary references: [CodeMirror autocomplete](https://github.com/codemirror/autocomplete), [Lezer Markdown API](https://github.com/lezer-parser/markdown), and installed `node_modules/@codemirror/{view,autocomplete,lang-markdown}/dist/index.d.ts`. The public CodeMirror decorations page returned 403 in this environment, so the installed view API was used to confirm actual version constraints. The archived GitHub repositories link to their current upstream hosting.

Registry access for declaring the already installed `@lezer/common` failed (`EAI_AGAIN`), and offline metadata was not cached (`ENOTCACHED`). The direct declaration was added to `package.json` and the lockfile root using the existing verified 1.5.3 resolution. `npm ls @lezer/common` passes and shows one deduplicated version. No new package binary or parser engine was fetched.

## Exact manual checklist

Use a format-2 scratch document and the current Vite development server or freshly built assets. Copy the contents of [the M3 manual fixture](../examples/orbium-markdown-m3.md) into the editor; there is no new file-import UI in this phase.

1. **Open/modes/source fidelity.** Open a new scratch document and paste the fixture. Expected: Live Preview is the initial presentation; H1/H2/H3/H6 sizes, inline marks, lists, quotes and divider render. Switching the Live Preview button to Markdown source restores all literal source and line numbers; switching back leaves text, selection/history and revision unchanged. Wait for Saved, reload and compare source with the fixture: expected exact source spelling apart from the existing LF normalization. Plain prose without Markdown markers stays prose; headings are not inferred from copied plain text.
2. **Block shortcuts.** On separate blank lines type `# `, `## `, `### `, `- `, `1. `, `- [ ] `, `> ` and `---`. Add ordinary text after the prefixes. Expected: heading/list/quote/task/divider presentation appears without requiring the slash menu. Moving the caret into a marker reveals it; Markdown source still contains the original markers. Enter continues lists/quotes; Enter/Backspace on an empty continuation exits according to CodeMirror's native Markdown behavior.
3. **Inline shortcuts/format keys.** Type `**bold**`, `*italic*`, `~~strike~~` and a backtick-delimited code span, then move outside the expression. Expected: delimiters hide and appearance matches the mark. Move inside: expected syntax is editable. Select a word and apply Ctrl/Cmd+B, Ctrl/Cmd+I or Ctrl/Cmd+Shift+X; apply the same shortcut again to the inner selected text. Expected: Markdown wraps/unwraps once; Undo/Redo restores source and selection. In a fenced/inline code region or a rich source-only line, these formatting shortcuts do not inject marks.
4. **Slash keyboard/pointer.** On an empty paragraph type `/`, then `heading 2`. Expected: a nearby menu filters to Heading 2; Enter inserts `## ` and leaves the caret ready to type. Reopen `/` and use Up/Down, Tab, Escape and pointer selection. Expected: Tab accepts the selected command, Escape leaves the slash text, and ordinary Tab outside list/menu context can leave the editor. Test `/` after whitespace in a prose line: expected block insertion preserves adjacent text. Ctrl+Space opens Search Master, not a second completion panel.
5. **All commands.** On separate blank paragraphs choose Text, Heading 1/2/3, Bullet list, Numbered list, Checklist, Quote, Callout, Code, Table, Mermaid, Math block, Inline math and Divider. Type text where the caret lands. Expected: slash/query disappear, a valid bounded Markdown template is inserted, ordinary blocks render, and rich blocks remain editable source. Save/reload: expected source persists without JSON conversion or silent flattening. Undo one command: expected its insertion reverses as one history group.
6. **Fence/nesting.** On a blank top-level line type three backticks followed by `js`, then Enter. Expected: a closing three-backtick line appears and the caret sits inside. Repeat with three tildes. Existing closed fences must not gain another closer. Type Markdown-looking text and `/heading` inside the code body: expected literal source, no slash menu or emphasis preview. In a list, Tab/Shift+Tab changes nesting and Enter continues at the right depth; Ctrl+M then Tab (Shift+Alt+M then Tab on macOS) provides a focus escape if needed.
7. **Tasks and undo.** Click the fixture's pending task checkbox; also Tab to a checkbox and press Space. Expected: only its `[ ]` / `[x]` marker changes; checkbox keyboard focus survives DOM updates. Undo/Redo restores checked state and save/reload preserves it. Edit above the task, then toggle it again: expected the mapped position changes the correct task. Switch away and try another tab's controls: expected the hidden document does not receive the action.
8. **Caret/selection/copy/find.** Arrow through bold/link/list syntax, select across several formatted lines, then Ctrl/Cmd+A and copy. Expected: no trapped caret, missing characters or hidden source loss. Find `bold` with Ctrl/Cmd+F and Enter/Shift+Enter: expected source matches select/scroll correctly and relevant syntax reveals. Searching `**` can intentionally match Markdown punctuation. A phrase separated by Markdown markers is not promised to match logical text in this phase. Close the finder: expected highlight/count clears without a second search panel.
9. **Safe links/literals.** Ctrl/Cmd+click the fixture's example link; also activate a focused link from the keyboard. Expected: a new protected tab opens the intended destination; ordinary click edits. Raw `<script>` remains visible literal source; `window.orbiumM3Executed` stays undefined. Reference-style links, encoded destinations and unsupported schemes remain source rather than guessed executable links. Server rejection of unsafe destinations still appears as a save error. Dollar math, callout headers, Orbium metadata and tables must retain their syntax until rich widgets exist.
10. **Image/File/cancel.** Choose `/Image`, select a small PNG/JPEG/GIF/WebP, then wait for upload and Saved. Expected: canonical `![name](orbium:attachment/<id>)` source persists and the upload uses the current document endpoint; image preview is M4. Choose `/File` with a small PDF/text file: expected `[name](orbium:attachment/<id>)`; the file link opens the authorized download. ### Changes

- Extracted the existing document presentation CSS into `resources/css/editor-document.css`, imported by the same global stylesheet. Tiptap keeps its existing rules. H1/H2/H3, quotes, inline code and divider presentation now share declarations with CodeMirror preview classes, preventing two independent default designs. - Ordinary blank Markdown separators use the existing 0.75em paragraph gap; fence/HTML/table source keeps its original line height. Heading space is measured using line padding instead of adding external margins to CodeMirror's line layout. A heading following a blank separator subtracts that separator's default height. - List markers use the existing 1.6em hanging indentation; task checkboxes use the same native size and 0.6em text gap. Quote styling extends to visible continuation lines. List/code nesting and composite-block container geometry still need the remaining migration parity work.

Rich/source-only blocks do not receive misleading rich preview selectors. Source mode does not receive document block overrides.

- Save status and error-only Retry sit at the left of the existing mb-7 control row. Source switch, Find and Add file use the existing compact icon-button appearance on the right.
