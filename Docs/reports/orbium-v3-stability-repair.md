# V3 stability repair — 2026-10-31

## Scope and result

The user approved repairs with “okey fix that” after the [stability investigation](orbium-v3-editor-stability-audit.md). This change addresses the code paths behind F01–F13 and adds safeguards for rejected code drafts, upload identity and cross-document persistence. It remains stage-6 bug repair; stage 7 has not started.

These are implementation and static-check results. None of the interactions below has been executed in a browser for this repair. No automated tests, fixture runners, Playwright, browser automation, database changes, migrations, staging or commits were performed. Existing uncommitted work was preserved. This report does not establish that every editor glitch has been eliminated.

## Additional risks: disposition

| Audit | Disposition and remaining boundary |
| --- | --- |
| R01 — performance | Column comparisons now materialize the before/after strings once instead of slicing CodeMirror Text for each character. Ordinary text-prefix validation avoids a full semantic check after every harmless content character. Full-source combined parsing/range mapping still exists. No latency measurement or performance acceptance is claimed. |
| R02 — rejected rich drafts | Rejected code content/language is retained by owner and stable block ID across widget remounts, shown as unsaved, and included in Copy. Discard draft explicitly restores accepted source. Mode/import/export, affected owner operations, keyboard history and navigation are guarded while the draft exists. Retry or successful further editing clears it. This is an in-memory recovery buffer, not a durable offline store; forcing the page closed can still discard unsaved work. Hosted persistence still belongs to the surrounding Board session; local navigation and code-draft guards apply. |
| R03 — upload anchors | Upload completion also verifies the originating block ID, in addition to mapped positions and source. A deleted/replaced/mis-mapped origin cannot silently receive the upload; the error includes a reusable reference. This does not promise following a block through every move: an ambiguous anchor fails safely. |
| R04 — linked persistence | A destructive source snapshot waits until a successful destination save contains the moved IDs and the latest queued body/type values. An older in-flight snapshot cannot authorize deletion merely because it has those IDs. Linked undo/redo installs the dependency in the reverse/forward direction. A conflicting additional move through either pending document is refused until persistence progresses, avoiding save cycles. Destination failure leaves source deletion unsaved and navigation guarded. This is ordered persistence, not a two-document server transaction: interruption may leave duplicate copies. Keep both documents open until both show Saved. |
| R05 — server admission | Server validation now checks every effective body node and rejects unrelated siblings outside presentation/rich containers. Client admission likewise validates changed/created typed bodies and saved source. Forced multiline heading content is one intentional heading; its resulting server AST is checked again against safety limits. Existing server metadata/security/ownership checks remain authoritative. |
| R06 — composition/history | Rich source typing uses a typing event without isolating every character into its own undo unit. Existing IME guards remain. Real OS composition, browser event order and undo grouping require manual verification. |
| R07 — interaction limits/notices | Whole-block typing/deletion has an explicit owner path, and successful document edits clear stale boundary notices. Partial text selections across different blocks, structural commands with multiple carets and cross-workspace native paste remain intentionally restricted. Unsafe actions give a boundary/type message; these restrictions were not silently expanded into new features. |

## Manual acceptance checklist

Use disposable V3 documents with the matching frontend/server build. For normal editing cases, finish by waiting for **Saved**, reloading, and confirming the same content. Check root text and a column child where applicable. Undo/redo should reverse one structural action without changing unrelated block identities. These boxes are deliberately unchecked.

- [ ] **Original screenshot case:** Create a paragraph, H1 and bullet list in that order. Click immediately above/below each visible block and type. Repeat after Source → Live and after reload. Expect normal existing spacing, visible typing in a real body, and no caret/typing on a hidden identity line. Deliberately inserted blank body lines must remain.
- [ ] **Typed content replacement (F01):** Put the caret inside an H1, press Ctrl/Cmd+A once, and type a new title. Repeat for bullet, numbered, checklist and callout content. Expect the block to keep its type and save. Reopen a document whose first block is a heading/list and type at its initial caret; expect typing after its required prefix.
- [ ] **Whole-block replacement:** Use handles and Shift selection to select two consecutive blocks, then type `Replacement`. Expect identified replacement, with neither old header left behind. Undo restores both blocks and IDs; redo restores the replacement. Repeat selection followed by Delete; the final-document case must leave a writable paragraph.
- [ ] **Empty typed exit (F02):** Insert an empty bullet, numbered list and checklist using `/`; press Enter without adding text. Expect a new paragraph and a valid retained empty typed block. With `first item` followed by an empty last item, Enter exits and removes only the final empty item. Test quote/heading empty exits too; all must save.
- [ ] **Rich-frame deletion (F03):** Focus the outer noninteractive frame of code, table and math, then press Delete and repeat with Backspace. Expect whole-block removal, correct neighboring content, valid final-document/final-column handling and complete undo restoration. Enter inside a code/table editor must keep its specialized meaning.
- [ ] **Writable insertion (F04/F13):** Between two paragraphs use the first gutter +, then type immediately. Repeat by pressing Enter on a rich frame. Align an empty paragraph before another block, press Enter in its input, then type; compare Shift+Enter. Expect a new usable paragraph with its own ID, without extra phantom gaps or a structural warning.
- [ ] **Column scope (F05/F11):** Put code/table in a column with another child after it. Focus its frame and press Enter, then repeat with a printable character. Repeat when the rich block is the last child. Expect the paragraph and caret in the same column, after the typed character where applicable. Check Source only after saving: the child's parent must be that column.
- [ ] **Caret intent (F06):** Place the caret in the middle of text, change alignment or direction, then type `X`. Expect insertion at the original visible position. Repeat in a heading and column. Style an empty paragraph and type two characters; expect normal order and no jump into wrapper syntax.
- [ ] **Multiline headings (F07):** In H1/H2, type a title, Enter, and another line; add bold text and an inline icon/link. Expect both lines and the active next blank line to retain heading typography within one ID. Reload, inspect a hosted preview, and export Office output. Expect retained heading content and line breaks. Native export/import must retain source/IDs; portable Markdown follows Markdown's own line-rendering limits.
- [ ] **First-rich escape (F08):** Make code/table the first block, focus its frame and press Up or Left. Expect a writable paragraph above; type and save. Repeat inside a column; insertion must stay in that column. Navigation between existing siblings should not create duplicate paragraphs.
- [ ] **Styled shortcuts (F09):** Apply alignment/direction to an empty paragraph. Type `# ` or `> ` and continue typing. Expect a heading/quote with compatible presentation retained and a useful caret. For list conversion clear incompatible alignment first; rejected incompatible presentation must preserve source and explain the action.
- [ ] **Native menu copy (F10):** Style a heading/list and copy it through its menu. Paste in the same workspace. Expect type, inline formatting and presentation retained with newly allocated copy IDs. Repeat for a selected consecutive range and a columns layout. Paste into a plain-text app to confirm readable text. Denied/unsupported clipboard access must show an actionable message; cross-workspace native paste must not silently import foreign references.
- [ ] **Layout boundaries (F11):** Put a two-column layout between paragraphs, then first and last in separate documents. Click/tab at each edge and type. Expect focus in a visible child or a real adjacent paragraph, without editing `:::orbium` syntax. Type/Enter after a last root layout; expect a paragraph afterward. Check narrow stacking and Source → Live too.
- [ ] **Safe drafts (F12):** Type `$$` at the first line of a paragraph, then Enter. Expect a complete math block. Draft a triple-backtick/tilde fence with a language and Enter; expect a closed code/Mermaid block. Repeat these openings after an internal paragraph newline; expect literal prose, with no missing characters. Draft `++block ` / `++endblock ` in ordinary prose; expect literal text, not new structure.
- [ ] **Code history and rejected draft (R02/R06):** Type a word in code and undo/redo; expect meaningful typing grouping. If a code sample with a line over 128 KiB is available, paste it to exercise owner rejection. Expect an explicit unsaved draft, Copy returning that draft, and retention after scrolling away/back. Mode switch, import/export, deletion/history and navigation must be guarded. Reduce the offending line and edit again to retry; alternatively Copy then Discard draft. Retry Save must clear a resolved draft error.
- [ ] **Delayed upload (R03):** Under manual network throttling, start an image/file upload into an empty paragraph. Before completion delete/replace that paragraph, or move it so the mapped text position no longer identifies it. Expect insertion only if the original ID/source still matches; otherwise a reusable-reference error and no insertion into a neighbor. Repeat unchanged origin; expect normal insertion and save.
- [ ] **Cross-document save ordering (R04):** Save two split documents first. In browser Network request blocking, block only the destination document's Markdown PUT URL. Move a block there. Expect destination save failure and source waiting rather than saving the deletion. Remove blocking and retry destination Save; expect both to reach Saved, then reload and find the block only at its destination. Repeat linked undo/redo, immediate undo before save, and a deliberately delayed older destination save. Old snapshots must not release deletion of newer moved content. While waiting, another move through those documents must be refused without changes. Do not force-close unsaved documents for ordinary acceptance.
- [ ] **Semantic Source failure (R05):** In Source mode, remove an H1's `# ` while retaining its `heading-1` identity, or append unrelated prose after a code block in that code body's ID. Save. Expect a clear body/type error and retention of source; correct it and save/reload. Do not interpret intentional heading internal lines as unrelated prose.
- [ ] **IME, performance and notices (R01/R06/R07):** Compose real Japanese/Chinese/Korean text in root, column, code, table and math inputs. Expect no premature structural action/save and intact committed text. Compare typing/scrolling/selection in small and genuinely large documents with many columns; record any lag rather than assuming a performance pass. Cause a partial cross-block rejection, then make a valid edit; expect the stale boundary notice to clear. Multi-caret structural commands remain intentionally refused.
